# 🤖 Регламент документации для AI-агентов

- **Статус:** актуально
- **Версия:** 2.0
- **Проверено:** 2026-10-03
- **Система принята в:** [ADR-0001](./adr/0001-documentation-system.md)

Обязательно к прочтению каждым агентом (человеком) перед первой правкой проекта.
Цель: документация отвечает на вопрос за ≤30 секунд и не врёт.

---

## 0. Иерархия правды

**код > AGENTS.md > любые документы (включая этот).** Обнаружил расхождение документа
с кодом — код главнее; расхождение = задача в `TODO.md` на исправление документа,
а не молчаливая подгонка текста под код или кода под текст.

## 1. Карта документов — `docs/README.md`

Единственная навигация по знаниям. Правила:

- Добавил / удалил / переместил документ → обнови карту **в том же PR** (пункт DoD).
- Ссылка из карты на несуществующий файл = ошибка (ловит `scripts/docs-check.sh`).
- Не можешь определить квадрант (тип) нового документа → он лишний.

## 2. Квадранты знаний (Diátaxis)

| Тип                 | Вопрос                    | Примеры                                        |
| ------------------- | ------------------------- | ---------------------------------------------- |
| **reference**       | «какая точно информация?» | INDEX.md, openapi.yaml, cheatsheets            |
| **explanation**     | «почему так устроено?»    | ARCHITECTURE.md, ADR, IDEAL-ARCHITECTURE       |
| **how-to**          | «как решить задачу?»      | DEBUG_INSTRUCTIONS, prompts/README             |
| **статусы/история** | «что и когда было?»       | PROGRESS.md, developer_log, датированные срезы |

Один документ — один тип. Дубли между типами запрещены: ссылайся, не пересказывай.

## 3. Freshness-заголовок (обязателен для каждого `docs/*.md`)

Первой секцией после заголовка:

```md
- **Статус:** актуально | устарел | архив
- **Проверено:** YYYY-MM-DD # дата последней сверки содержимого с кодом
```

Правила:

- `устарел` — документ не отражает код, но исторически ценен: пометь и укажи, что
  вместо него. Не удалять молча.
- Дата `Проверено` старше 6 месяцев у документа из живых секций карты → задача на
  сверку (архитектор заводит при вехе, см. PROGRESS).
- Сверка = прочитать и подтвердить соответствие коду; при изменении кода, которое
  документ описывает, — обновить документ в том же PR.

## 4. Что где живёт

| Контур  | Путь                     | Что                                    | Жизненный цикл                                               |
| ------- | ------------------------ | -------------------------------------- | ------------------------------------------------------------ |
| Знания  | `docs/`                  | reference/explanation/how-to/статусы   | живут, freshness-контроль                                    |
| Решения | `docs/adr/NNNN-*.md`     | ADR (MADR, шаблон `_templates/adr.md`) | неизменяемы; смена решения = новый ADR                       |
| Процесс | `devAI/spec/`            | SPEC-NNN, TASK-BATCH-NNN, планы задач  | статусы ⬜/🔄/✅; закрытые — список в `devAI/spec/README.md` |
| Сессия  | `devAI/PLANNING.md`      | план текущей задачи                    | задача закрыта → итог в developer_log; файл один, не плодить |
| Лента   | `devAI/developer_log.md` | append-only журнал агентов             | никогда не удалять/править записи                            |
| Роли    | `prompts/`               | ролевые промпты агентов                | версионируются как код                                       |
| Архив   | `docs/archive/`          | датированные срезы >6 мес              | только склад, без правок                                     |

## 5. Строгие запреты

1. **НЕ создавать** в `docs/` файлы `plan-*.md`, `tz-*.md`, `*_SPEC/*_TASK/*_PLAN.md`
   — рабочий материал живёт в `devAI/` (урок kino-club: 150+ планов в docs/ без
   индекса = свалка).
2. **НЕ удалять записи** из `devAI/developer_log.md` (только append).
3. **НЕ править принятые ADR** — только Supersede новым.
4. **НЕ обновлять карту «потом отдельно»** — только в том же PR.
5. **НЕ плодить дубли:** информация живёт в одном месте, остальные ссылаются.

## 6. Обязанности ролей (`prompts/`)

- **Архитектор** — владелец системы: карта, freshness при вехах, ADR на решения,
  PROGRESS на вехах.
- **Кодер/отладчик/дизайнер** — append в `developer_log`; `INDEX.md` при изменении
  структуры; документ из карты — при изменении того, что он описывает (в том же PR).
- **Аналитик** — фиксирует найденные дрейфы (не правит документ молча).

## 7. Автопроверка — `scripts/docs-check.sh`

Запуск: `bash scripts/docs-check.sh` (входит в DoD задач, меняющих `docs/`). Проверяет:

1. Все markdown-ссылки карты `docs/README.md` указывают на существующие файлы.
2. Каждый `docs/*.md` (кроме карты и этого регламента) имеет freshness-заголовок
   (`Статус:` и `Проверено:`).
3. ADR пронумерованы без дыр и имеют статус.
4. `docs/PROGRESS.md` существует и не пуст.

Скрипт не проверяет смысл — семантическую свежесть сверяет архитектор/человек.

## 8. Чек-лист агента (после правок)

1. Код написан и проверен (gates AGENTS.md §8).
2. `INDEX.md` обновлён, если изменились структура/файлы/типы/зависимости.
3. Документ из карты обновлён, если менялось то, что он описывает.
4. Карта обновлена, если документы добавлялись/удалялись/двигались.
5. Freshness-заголовки обновлены (`Проверено:` = сегодня) у тронутых документов.
6. `developer_log.md` дополнен; задача из `TODO.md` удалена/зачеркнута.
7. `bash scripts/docs-check.sh` — зелёный.
8. Архитектурное решение принято и нет ADR → завести ADR.
9. Просьба к человеку закоммитить (коммит — по AGENTS.md §10).
