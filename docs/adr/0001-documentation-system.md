# ADR-0001: Система документирования v2 (Diátaxis + ADR + freshness-контроль)

- **Статус:** Accepted
- **Дата:** 2026-10-03
- **Автор:** ZCode (по запросу владельца)
- **Заменяет:** — (эволюция правил из AI_DOCUMENTATION_GUIDELINES.md v1.0)

## Контекст

Документация проекта деградировала тремя наблюдаемыми способами:

1. **Карта врала:** docs/README.md (v1.1, 2026-04-17) ссылалась на 6 уже удалённых
   файлов (TECHNICAL_SPECS, E2E_*, developer_log в docs/) — некто удалял файлы,
   не обновляя карту.
2. **Дрейф содержимого с реальностью:** ARCHITECTURE.md описывал БД как MySQL
   (8 упоминаний, `"mysql2"` в примере зависимостей) при фактическом
   PostgreSQL + `pg` в `server/package.json`; AI_DOCUMENTATION_GUIDELINES v1.0
   предписывала вести PROGRESS.md и FRONTEND-STATUS.md, которых физически нет.
3. **Опыт соседних проектов:** kino-club накопил 150+ `plan-*.md`/`tz-*.md` россыпью
   в docs/ без индекса и статусов — рабочий материал вытеснил знания; private-cinema
   ближе к порядку (prompts/, датированные находки), но планы так же размазаны.

Пользовательские задачи (планы/ТЗ) и знания (архитектура/справочник) смешаны в одном
месте; решения «почему так» нигде не фиксируются и теряются между сессиями агентов.

## Решение

Принимаем систему из шести компонентов:

1. **Diátaxis-квадранты** для знаний в `docs/`: reference / explanation / how-to /
   статусы-история. Один документ = один тип; дублирование запрещено.
2. **ADR (MADR)** в `docs/adr/`: неизменяемые, нумерованные записи решений;
   смена решения = новый ADR + Superseded.
3. **Freshness-заголовки** у каждого `docs/*.md`: `Статус:` (актуально/устарел/
   архив) + `Проверено:` (дата сверки с кодом). Дрейф документа с кодом = задача
   в TODO (как минимум), а не молчаливая подгонка.
4. **Разделение контуров:** знания — `docs/`; процессный материал (спеки, ТЗ,
   task-batch'и, планы сессий) — `devAI/` со статусами и списком; лента работы —
   `devAI/developer_log.md` (append-only); роли агентов — `prompts/`.
5. **Карта `docs/README.md` — единственная навигация**, обновляется в том же PR,
   что и изменение документов; ссылка на удалённый файл = ошибка (ловит
   `scripts/docs-check.sh`).
6. **Архив вместо удаления** для датированных срезов старше 6 месяцев: `docs/archive/`.

## Варианты, рассмотренные и отклонённые

- **Вики/GitHub Wiki вне репо** — теряется docs-as-code: ревью и синхронность с PR.
- **Оставить как есть ( guidelines v1 + INDEX-монолит)** — деградация продолжается,
  что и наблюдалось.
- **Полный перенос планов в docs/ со статусами (модель kino-club)** — проверено
  соседями: рабочие документы вытесняют знания, индекс не выдерживает.

## Последствия

**Стало лучше:** один вход (карта); ответы «почему» не теряются (ADR); дрейф
обнаружим (freshness + docs-check.sh); процессный материал не размазан по docs/.

**Стало хуже / риски:** дисциплина заголовков — дополнительная обязанность агентов;
docs-check.sh покрывает только ссылки/заголовки, семантическую свежесть проверяет
человек/архитектор на вехах.

**Митигации:** docs-check.sh в DoD крупных задач; при вехе — сверка freshness-дат
регламента; ADR-шаблон снижает порог входа.
