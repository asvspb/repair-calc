## Цель (проверяемая)

Каждый документ из списка сверен с кодом по заявленным в нём фактам; в шапке каждого —
актуальная дата «Проверено: YYYY-MM-DD» ИЛИ документ переименован/помечен как
исторический; все найденные расхождения внесены в реестр дрейфов `docs/README.md`;
P2-2 закрыт.

## Документы (write — ЭКСКЛЮЗИВНО)

- `docs/LOGGING.md`, `docs/LOGGING-CHEATSHEET.md` — сверка с `server/src/middleware/logger.ts` (winston), `src/utils/logger.ts`
- `docs/ARCHITECTURE.md` — сверка ПОЛНОСТЬЮ (в прошлый проход — только блок БД); канон состояния теперь zustand (`src/store/`), НЕ Context — если в тексте другое, исправить
- `docs/IDEAL-ARCHITECTURE.md`, `docs/TECHNICAL-SPECIFICATION.md`, `docs/CODE_REVIEW.md` — сверка фактов (существование модулей/команд/инструментов)
- `docs/README.md` (реестр дрейфов + статусы freshness), `devAI/developer_log.md`

## Правила сверки

1. Для каждого фактического утверждения в документе — проверить по коду/grep (существование файла, команды, версии, порты).
2. Утверждение верно → оставить; неверно → исправить НА КОД (не подгонять код); существенная разница, которую нельзя решить правкой дока → строка в реестр дрейфов.
3. Документ описывает нереализованное видение (IDEAL-ARCHITECTURE) → явно пометить «видение, не текущее состояние» и не проставлять «Проверено» как текущее.
4. Устаревшие документы — не удалять, а переносить ссылку в `docs/archive/` по регламенту ADR-0001.

## Запреты

- НЕ менять код — только документы.
- НЕ проставлять «Проверено» без фактической сверки (каждая дата = список проверенных утверждений в developer_log).
