1. **`deleted_entities` — «мёртвая» таблица (§15.2.0).** Создана миграцией, но ни одна запись не пишется и не читается (grep: только миграция). Вся подсистема «мягких удалений с TTL-синхронизацией» фактически заменена на `deleted_at` + 90-дневный archive-cleanup (`cleanupDeleted.ts`). Требование §15.2.0/15.2.2 повисло в воздухе — решения (ADR/TODO) не найдено.
2. **sync/pull не отдаёт блок `deleted` (§15.2.2).** Клиент не может узнать об удалённых на сервере сущностях через pull (компенсация — LWW-merge в `syncMerge.ts` по SYNC-V2 спеке, но это другой контракт). Требование не закрыто и не отклонено формально.
3. **Премиум-модель не реализована (§10.2).** `users/me` хардкодит `is_premium: false`; нет ни апгрейда, ни гейтинга Excel (Excel-экспорта сметы нет вовсе — только CSV), ни гейтинга AI. Монетизационная часть ТЗ не выполнена; в TODO бэклога нет.
4. **`is_premium` из БД не читается в `/api/users/me` (§6.1.0).** Поле в users есть, репозиторий объекта его использует, но профиль всегда отдаёт `false` (`users.ts:35`) — рассинхрон контрактов.
5. **Перривязка `calculated_totals`/`ai_requests` к объектам (§15.6.1, §15.7.1, §15.8) не сделана.** Обе таблицы остаются project-scoped. Функционально компенсировано клиентским расчётом итогов по объектам, но требование ТЗ не переформулировано.
6. **Deprecation-middleware не подключён к маршрутам (§15.3.2).** Реализован и протестирован, но ни один эндпоинт не помечен устаревшим — «логирование запросов к старым эндпоинтам» фактически не работает (известно из §0.1, решение отложено архитектору).
7. **API-версионирование `vnd.repair-calc.v2+json` отсутствует (§15.3.1).** Grep пуст; v1/v2 сосуществуют без версий. Sunset-дата из ТЗ (01.06.2026) истекла — требование устарело.
8. **Формат экспорта отличается от ТЗ (§8.2, §15.9.1).** Бэкап всех проектов + workTemplates вместо одного проекта с `objects`; отдельные уровни экспорта (объект/комната) не реализованы. Совместимо с v1-импортом, но формат не зафиксирован нигде, кроме кода.
9. **POST/PUT объектов без Zod-валидации (§15.10).** Остальные сущности валидируются Zod; объекты — ручная деструктуризация (`objects.ts:23,137`). Единообразие из ТЗ нарушено.
10. **`ChangeLogEntry` не включает entity `object` типобезопасно (§15.2.1).** Сервер сравнивает `change.entity as string` с комментарием-извинением (`sync-v2.service.ts:74`) — работает, но хрупко.
